The KnitAdvisor API

Use the same engines as the website — the fabric calculator, the Fabric Studio, the costing sheet and dyeing — from your own system: your ERP, your PLM, your quotation tool. You send JSON, you get JSON back.

1. Get a key

API access is a plan, bought in your account under "API access": pick a plan and the months, pay as shown there, and give the transaction id. When KnitAdvisor has checked the payment, a button appears in your account that creates your key. It looks like ka_live_…, is shown to you once, and acts as your account on the engines below. Keep it on your server — like a password. Renewing or upgrading extends the same key.

Always send the email you sign in with (the account that owns the key). Your keys, their plan, and how much of the month is used are in the same place. There you can also name a key, say which server IP addresses it may be used from, and which websites may use it from a browser.

2. Make a call

Every call carries three things that must agree: your key (as a Bearer token), the email of the account that owns the key in X-User-Email, and the website the key is registered to. From a server you name the website in X-Website (for example https://erp.yourmill.com, no path); a web page sends it by itself as its Origin. A key with no email, another account's email, or another website, is refused. Every endpoint is under /api/v1.


    
The answer is JSON. The calculator's answer has the yarn, stitch length, shrinkage, machine and cost sections; success: false and an error tell you what to fix.

Every answer carries your position:

    

      
X-RateLimit-Limit · X-RateLimit-Remainingcalls allowed and left in the current minute

      
X-Quota-Limit · X-Quota-Remainingcalls allowed and left this month

      
X-Quota-Resetwhen the month's count starts again (1st of the month, Dhaka time), ISO 8601

      
Retry-Afteron a 429: seconds to wait

    

    
GET /api/v1/usage returns the same for the key you call it with, plus the last 30 days, day by day. A call that is refused (a bad key, over the rate) is not counted against the month; a call that reaches an engine and returns an error is.

6. Keep it safe

    
    
      
  • The website is part of the key. From a browser it is checked against the page's real Origin, which a web page cannot fake; a call from a server names it in X-Website, which anyone holding the key could write — so it makes a wrong key and wrong system obvious, but the IP address list is what stops a stolen key. A key used in a web page is visible to its visitors: give it a small plan. A key with no website registered refuses every browser call.
    • 
      
  • Ask for an allowed-IP list: then a copied key is useless from anywhere but your servers.
    • 
      
  • A key found in the wrong hands is revoked by KnitAdvisor at once, and a new one issued; nothing else of yours changes.
    • 
      
  • The API returns what your account would see on the website. Your saved designs, costing sheets and calculation history are not reachable with a key.
    •
